# plans/

Implementation specs, written **before** the work starts. Numbered `001-`,
`002-`, … in the order they were opened.

A plan is edited freely while it is being scoped, and marked `Status: accepted`
once execution begins — after that, changes of direction are recorded as
amendments at the bottom rather than by rewriting the middle, so the plan still
explains the code that exists.

A plan is not an ADR. Plans describe *how and in what order*; decisions and
their reasoning go in [`../adr/`](../adr/). If a plan finds itself arguing for
one approach over another, that argument belongs in an ADR the plan links to.

Delete nothing here. A finished plan is the answer to "why is it built this
way" for as long as the code lives.
